### 3.4 Asset folders now mean one thing each

Five Drive folders had been configured since 2026-07-25 (**by the operator, not

`rejected` and `published` are now written to. Three rules that matter:

### 3.6 The biggest finding of the session — positional coupling

**Read this part carefully. It changed the architecture.**

The workbook joined its tabs with position-bound formulas:

```
Content Pipeline  B2 = IF('Content Calendar'!D2:D1000="","",
                         'Content Calendar'!D2:H1000)
Content Pipeline  G2 = IF('Campaign Cards'!O2:O1000="","",
                         'Campaign Cards'!O2:Z1000)
Visual Pipeline   2,244 individual cells, each 'Content Pipeline'!<cell>
```

Two array formulas anchored in **row 2** fed the entire Content Pipeline.

Delete Content Calendar rows 2–50 and that array re-renders from the new source
range: pipeline row 2 now shows what used to be calendar row 51 — while `S:AX`
on row 2, everything the workers wrote, never moved. **Every post's strategy ends
up paired with a different post's copy. No `#REF!`, no error, nothing that looks
wrong.** Deleting row 2 itself destroys the transfer permanently.

This is not an archiving hazard. **One row deleted by hand does the same thing
with no code involved.**

`Transfer.gs` replaces both hops with values written once and joined by a key
the row carries: `Calendar ID` into the Content Pipeline, `Content ID` into the
Visual Pipeline. Transfers are idempotent — a row whose key is already
downstream is skipped, so running twice is a no-op.

`Ads Pipeline` has always worked this way (written by `AdsRunner`, keyed on
`Content ID`, no formulas) and was the model.

New menu item: Planning → **Transfer Rows Forward**.

### 3.7 Archiving, rebuilt on that foundation

One hidden `Archive` sheet, **one row per post**, joined across all four tabs —
scheduled, written, produced, advertised — with each fact stored once.
`Ads Pipeline` was the tab easiest to forget and is included.

Deletion runs **furthest-downstream first** (Ads → Visual → Pipeline → Calendar)
and bottom-up within each sheet. Rows are written and **counted** before anything
is deleted. The operator types the batch id to confirm.

`Archive.assertNoTransferFormulas()` **refuses to run** while any transfer
formula remains, by reading the sheet rather than trusting a flag.

### 3.9 Two bugs this session introduced and then caught

Worth knowing because you may repeat them:

- **`\b` does not work on Arabic.** JavaScript defines it on `[A-Za-z0-9_]`, so
  `/\bنضمن/` matches nothing, silently, and the check then reports all clear.
  `START_HERE.md` §7 already documents this against the portfolio critic — and
  writing `AdPolicy.scan` reproduced it. Three of four rules were dead on
  arrival. Use `(?![؀-ۿ])` as the boundary.
- **Weak assertions.** Mutation testing found three checks that could not fail:
  an ordering assertion that passed when the guard was absent entirely
  (`indexOf` returns `-1`, less than everything), a check matching a variable
  name still present after its guard was removed, and one reading a cached
  object instead of the mutated file.

**Mutation-test every guard you write.** A check that cannot fail is decoration.

### 5.1 Why it is safe — verified, not assumed

| Check | Result |
|---|---|
| Global name collisions between files | **zero** — every global is owned by exactly one file |
| Code executing at load time | **8 statements**, all plain literals (arrays, strings, numbers), none referencing another file |
| Circular dependencies | present, and harmless — Apps Script loads everything into one namespace before calling anything |

These are not modules. There is no `import`. Every file already puts its objects
into the same global scope. **Merging changes the number of files, not the
behaviour.**
