## إيه اللي حصل ولزمة الأمر ده

في `WORK_ORDER_MESSENGER_GO_LIVE.md` كانت المهمة 3 بتقول: نفّذ `UPDATE` على جدول
`BrandSocialAccount` عشان تحطّ أرقام الصفحات الحقيقية مكان `placeholder`.

**الأمر ده كان غلط مني، مش منك.** أنا افترضت إن الصفوف موجودة بقيم مؤقتة
ومحتاجة تعديل. الحقيقة إن **الجدول فاضي تمامًا (0 صفوف)** — و`UPDATE` في SQL
**مابيضيفش صفوف جديدة**، هو بيعدّل الموجود بس. فالتلات أوامر نفّذت بنجاح وماعملت
أي حاجة. تشخيصك كان صح ووقوفك وإبلاغك كان الصح.

**المطلوب `INSERT` مش `UPDATE`.**

## ليه ده مهم — مش خطوة شكلية

راجعت الكود (`messenger.adapter.ts` دالة `toInbound`): لما تيجي رسالة، الكود
بيدوّر على صف في `BrandSocialAccount` مطابق لرقم الصفحة و`isActive = true`،
عشان يعرف الرسالة دي جاية لأي مستشفى. **لو مالقاش صف، بيرمي الرسالة تمامًا**
ويسجّل تحذير — وده تصميم مقصود ومكتوب في تعليق الكود: *"الرد باسم المستشفى الغلط
أسوأ من عدم الرد"*.

**النتيجة العملية:** المشغّل يقدر يدوس Verify and Save في Meta وينجح (وده اتأكد
فعلًا، الـ webhook رجّع 200)، وبرضه **أول رسالة حقيقية هتترمي في صمت**. فالماسنجر
مش شغّال لحد ما الجدول ده يتملى.

# المهمة 2 — إضافة صفوف الربط

نفّذها **بس** لو المهمة 1 طلّعت التلات علامات.

```bash
docker exec insan-db psql -U insan -d insan <<'SQL'
BEGIN;

INSERT INTO "BrandSocialAccount"
  (id, "brandId", platform, "pageId", "pageName", "isPrimary", "isActive", "createdAt", "updatedAt")
SELECT
  gen_random_uuid()::text,
  b.id,
  'FACEBOOK'::"SocialPlatform",
  v.page_id,
  v.page_name,
  true,
  true,
  now(),
  now()
FROM (VALUES
  ('INSAN',  '1234349709765899', 'INSAN'),
  ('FUTURE', '1404631922892169', 'Future Specialized Hospital'),
  ('DELTA',  '435159743012313',  'Delta International Hospital')
) AS v(brand_code, page_id, page_name)
JOIN "Brand" b ON b.code = v.brand_code
WHERE NOT EXISTS (
  SELECT 1 FROM "BrandSocialAccount" x
  WHERE x."brandId" = b.id AND x.platform = 'FACEBOOK'::"SocialPlatform"
);

SELECT b.code, s.platform, s."pageId", s."pageName", s."isActive"
FROM "BrandSocialAccount" s
JOIN "Brand" b ON b.id = s."brandId"
ORDER BY b.code, s.platform;

COMMIT;
SQL
```

### إيه اللي بيعمله الأمر ده بالتفصيل

- **بيجيب `brandId` بنفسه** من كود العلامة (`JOIN ... ON b.code = v.brand_code`)
  — فمش محتاج تعرف أو تلصق أي `id` بإيدك.
- **`NOT EXISTS`** معناها لو اتنفّذ الأمر مرتين بالغلط **مش هيكرّر الصفوف**. آمن
  للإعادة.
- **`'FACEBOOK'::"SocialPlatform"`** تحويل صريح للنوع — العمود ده enum في
  Postgres ومحتاج التحويل ده.
- أرقام الصفحات دي مؤكدة، **متغيّرهاش**:
  - INSAN = `1234349709765899`
  - FUTURE = `1404631922892169`
  - DELTA = `435159743012313`

> ℹ️ عمود `pageName` **اسم للعرض بس** — التوجيه بيحصل بـ `pageId` وحده. فلو
> المشغّل عايز يصحّح الأسماء دي بعدين، مش هيأثر على شغل الماسنجر خالص.

## ✅ شرط النجاح — الصق الناتج

لازم تشوف:
1. سطر **`INSERT 0 3`**
2. جدول فيه **3 صفوف FACEBOOK** بالأرقام الحقيقية و **`isActive = t`**

| لو طلع | المعنى |
|---|---|
| `INSERT 0 3` + 3 صفوف `t` | ✅ خلصنا |
| `INSERT 0 0` | الصفوف موجودة بالفعل (حد نفّذها قبلك) أو `Brand` ناقص — **بلّغ** |
| `INSERT 0 1` أو `0 2` | علامة أو اتنين ناقصين من `Brand` — **بلّغ بالناتج** |
| أي `ERROR` | **بلّغ بنص الخطأ كما هو، متحاولش تصلحه** |

> صفوف INSTAGRAM و LINKEDIN **مش المفروض تتضاف** — إحنا بنشغّل فيسبوك بس دلوقتي.
