- **التحقق من المدخلات يعمل:** كل الحمولات غير الصالحة تُرفض بـ 400 ✓
- **معالجة 404 صحيحة** على الصفحات الجديدة ✓

## المشاكل

### 🔴 P-1 · لا توجد أي إمكانية لرفع الصور — الفجوة الجذرية

بحثت في المشروع كله فوجدت:

| ما بحثت عنه | النتيجة |
|-------------|---------|
| مكوّن `ImageUpload` | ❌ **غير موجود** |
| endpoint رفع في الـ API | ❌ **غير موجود** (لا `FileInterceptor` ولا `multer`) |
| مكتبة الوسائط `/admin/media` | ⚠️ **صفحة "قادمة قريباً" فقط** (17 سطر) |
| رابط الوسائط في القائمة الجانبية | ❌ غير موجود — الصفحة يتيمة |

> **ملاحظة مهمة:** التعليمات التي أرسلتَها لي تقول «استخدم `<ImageUpload />` بدل `<input type="file" />`». **هذا المكوّن غير موجود في المشروع إطلاقاً.** التعليمات تصف حالة مرغوبة لا حالة قائمة.

**هذا يفسّر كل مشاكل الصور (D-1 و D-2 و D-3).** الطريقة الوحيدة حالياً لإضافة صورة هي كتابة رابطها يدوياً كنص + رفع الملف على السيرفر عبر SSH.

### 🔴 P-2 · الإنتاج يشغّل كوداً غير موجود في أي فرع على git

قارنتُ كود الإنتاج الحيّ بكل الفروع:

```
الحيّ:  fixed bottom-[100px] md:bottom-24 right-4 md:right-auto md:left-8 z-[100000]
        origin-bottom-right md:origin-bottom-left
الريبو: fixed bottom-6 left-6 z-50 ... origin-bottom-left
```

الكلاسات الموجودة على الإنتاج **غير موجودة في `origin/main` ولا `origin/master` ولا فرع الإصلاحات.**

**السبب:** `deploy.ps1` يرفع أرشيف `tar` من مجلد العمل المحلي — **لا يرفع من git**. أي تعديل غير مرفوع (uncommitted) يصل للإنتاج ويختفي من التاريخ.

**الخطورة:** لا يمكن إعادة إنتاج ما يعمل حالياً. لو انهار السيرفر، الكود الحيّ **ضائع**. لا rollback ولا مراجعة ولا تتبّع — في منصة صحية.

### 🔴 P-3 · مجلد `public/` فارغ في git لكن الإنتاج يخدم منه ملفات

```
في git:      apps/web/public/  →  .gitkeep فقط (لا شيء آخر)
على الإنتاج: /images/journey/find-doctor.png  → 200 ✓
             /uploads/1785306943275-685786143.jpg → 200 ✓
```

هذه الملفات وُضعت يدوياً على السيرفر. **أول `docker compose up --build` نظيف من الريبو سيمحوها كلها** — وستتحول كل صور الموقع العاملة إلى 404 دفعة واحدة.

### 🟠 P-4 · روابط مكسورة في الفوتر (5 روابط)
```
/services/emergency    → 404
/services/icu          → 404
/services/outpatient   → 404
/services/radiology    → 404
/services/surgeries    → 404
```
قسم «خدماتنا» كامل في الفوتر يؤدي إلى صفحات غير موجودة، على كل صفحة في الموقع.

### 🟠 P-5 · صفحتان في الأدمن غير موجودتين
حسب مخرجات `next build`، هاتان الصفحتان **ليستا route أصلاً**:
```
/admin/profile      ← غير موجودة
/admin/settings/ai  ← غير موجودة (البديل الموجود: /admin/ai-assistant)
```
🔍 **(تحتاج تأكيدك بعد تسجيل الدخول)** — لكنهما غير موجودتين في القائمة الجانبية أيضاً، فالأرجح أنهما لم تُبنيا.

### 🟡 P-6 · خبر منشور بتاريخ نشر فارغ
```
opening-new-branch → status: PUBLISHED, publishedAt: null, صورة: لا يوجد
```
`NewsCard` يعرض شارة التاريخ فقط عند وجود `publishedAt` — فالخبر يظهر بلا تاريخ. كما أن الترتيب `orderBy: publishedAt desc` يضع `null` في مكان غير متوقع. يجب منع النشر بدون `publishedAt`.

## المشاكل

### 🔴 S-1 · الموقع كله على HTTP — بلا تشفير (لم يُصلَح بعد)
```
http://169.58.77.61/admin/login   ← كلمة مرور الأدمن تمر بنص صريح
```
`infra/nginx.conf` فيه `listen 80;` فقط — **لا يوجد بلوك `listen 443 ssl` إطلاقاً**، رغم أن `docker-compose.prod.yml` ينشر المنفذ 443 ويركّب مجلد `./infra/ssl`.

**ما يمكن لمهاجم على نفس الشبكة فعله:** التقاط كلمة مرور الأدمن، وسرقة توكن الجلسة، وقراءة/تعديل بيانات المرضى أثناء النقل.

> ⚠️ لمنصة صحية تتعامل مع بيانات مرضى، هذا أخطر بند مفتوح حالياً.

### 🔴 S-2 · لا توجد أي حماية من تخمين كلمة المرور
**اختبار فعلي — 48 محاولة دخول متتالية بحساب وهمي:**
```
48 محاولة → 48 × HTTP 401 → صفر × HTTP 429
```
لا إبطاء، لا قفل حساب، لا CAPTCHA، لا تأخير تصاعدي.

الحد الوحيد هو الحد العام `X-RateLimit-Limit: 100` أي **100 محاولة/دقيقة/IP = 144,000 محاولة يومياً**.

**واجتماع هذه العوامل يضاعف الخطورة:**
1. بريد الأدمن معروف ويمكن تخمينه (`admin@insan-platform.com`)
2. لا تشفير (S-1) — فالمرور بالنص الصريح أصلاً
3. لا مصادقة ثنائية

### 🟠 S-3 · تطبيق الويب بلا رؤوس حماية — لوحة الأدمن قابلة للـ Clickjacking

الـ API محمي بـ Helmet، لكن **صفحات Next.js (وهي التي يراها المستخدم وفيها لوحة الأدمن) شبه عارية**:

```
الموجود:  X-Content-Type-Options: nosniff        ← الوحيد
المفقود:  Content-Security-Policy                ← لا حماية من XSS
          X-Frame-Options / frame-ancestors      ← Clickjacking ممكن
          Referrer-Policy
          Permissions-Policy
```

**السيناريو العملي:** مهاجم يضع `/admin` داخل `<iframe>` شفاف في صفحة يسيطر عليها، ويخدع أدمن مسجّل الدخول ليضغط أزراراً دون علمه (حذف مستشفى، تعديل صلاحيات).

### 🟡 S-4 · كشف معلومات تقنية
```
X-Powered-By: Next.js
Server: nginx/1.31.3
```
يسهّل على المهاجم استهداف ثغرات معروفة لهذه الإصدارات تحديداً. خطورة منخفضة لكن الإخفاء مجاني.

# 👤 رابعاً: من وجهة نظر عميل / مريض

أنا مريض أبحث عن مستشفى لعملية جراحية. هذا ما أراه فعلياً:

### 🔴 U-1 · بيانات تواصل متضاربة على الصفحة نفسها
```
الشريط العلوي:  info@insan-platform.com
الفوتر:         info@hospitalgroup.com     ← شركة أخرى تماماً!
الفوتر:         +20 000 000 000            ← رقم وهمي
قسم التواصل:    0123 456 7890              ← رقم وهمي آخر
```
**كمريض:** لا أعرف أي بريد حقيقي. ورؤية اسم شركة مختلفة (`hospitalgroup`) تجعلني أشك أن الموقع منسوخ من قالب جاهز. ورقم `000 000 000` يعني «لا أحد يرد».

**النتيجة المباشرة: لن أتصل، ولن أحجز.**

### 🔴 U-2 · تقييمات ومواعيد مفبركة
```
"تقييم 4.9/5"                      ← ثابت في الكود
"4.9/5 · 1,234 تقييم"              ← ثابت في الكود
"الموعد المتاح القادم — اليوم 2:30 مساءً — د. سارة جونسون"   ← موعد وهمي وطبيب غير موجود
```
**«د. سارة جونسون» ليست من أطباء المنصة** (الموجودان: د. سارة كمال، د. أحمد محمد). اسم أجنبي مترجم من قالب.

وفي كل بطاقة طبيب:
```
"أكثر من 10 سنوات خبرة"    ← نفس النص للطبيبين
"5.0 (127 تقييم)"          ← نفس الرقم للطبيبين
```

**كمريض:** لو اكتشفت أن التقييمات مفبركة، أفقد الثقة في **كل** ما يقوله الموقع — بما فيه المؤهلات الطبية.

> ⚖️ **تنبيه:** عرض تقييمات ومراجعات مفبركة كأنها حقيقية يُعدّ إعلاناً مضللاً في معظم الأنظمة القانونية، وأشدّ صرامة في القطاع الصحي.

### 🔴 U-3 · إحصائيات ثابتة لا تتغيّر

# 🏥 خامساً: من وجهة نظر طبيب / إدارة مستشفى

أنا مدير تسويق في مستشفى الدلتا. اشتريت هذه المنصة لأدير حضوري الرقمي:

### 🔴 H-1 · لا أستطيع رفع صورة واحدة
هذا أخطر ما يواجهني. لا يمكنني:
- رفع صورة طبيب جديد
- رفع صورة لمركز طبي

**الطريقة الوحيدة:** أرسل الصور لمطوّر يرفعها على السيرفر عبر SSH ويعطيني رابطها لألصقه يدوياً.

**كعميل دفع ثمن نظام إدارة محتوى:** هذه ليست ميزة ناقصة، بل **نقض لجوهر المنتج**.

### 🔴 H-2 · لا أستطيع تصحيح بيانات أطبائي
```

```
د. أحمد لديه **20 عاماً** خبرة (مكتوبة في نبذته)، والموقع يقول 10. لا يوجد حقل لسنوات الخبرة أصلاً، ولا حقل للمؤهلات أو الشهادات.

**طبياً:** عرض مؤهلات غير دقيقة لطبيب مسألة حساسة مهنياً وقانونياً.

### 🔴 H-3 · صفحة مستشفاي شبه فارغة رغم أن الميزات موجودة
السيكشنات السبعة **مبنية وتعمل**، لكن لا أحد ملأ بياناتها. النتيجة: سيكشن الأقسام مخفي، وسيكشن التواصل والخريطة **مخفي بالكامل**.

🔍 **(تحتاج تأكيدك)** — التبويبات الخمسة الجديدة في نافذة تعديل المستشفى (الأساسية / Hero / الأقسام / رحلة المريض / التواصل والمواقع) موجودة ومنشورة، لكنني **لم أتمكن من اختبار حفظها فعلياً** لعدم قدرتي على تسجيل الدخول. **هذا أهم اختبار عليك إجراؤه** (الخطوة 1 في الخطة أدناه).

### 🟠 H-4 · لا خريطة لأي مستشفى
```

future-hospital → googleMapsUrl: false
```
**كمستشفى:** المريض لا يستطيع معرفة موقعي أو الحصول على اتجاهات. هذا أهم شيء بعد رقم الهاتف.

### 🟠 H-5 · لا أستطيع إدارة الأسئلة الشائعة
الصفحة موجودة والـ endpoint يعمل، لكن **لا توجد شاشة في الأدمن لإضافة سؤال** ولا رابط في القائمة الجانبية. النظام يقرأ من جدول `FaqItem` لكن لا سبيل لملئه إلا مباشرة من قاعدة البيانات.

### 🟡 H-6 · مزامنة فيسبوك تنشر مسوّدات
غيّرت سلوك المزامنة سابقاً لتستورد المنشورات كـ **مسودة (DRAFT)** بدل نشرها فوراً — وهذا صحيح تحريرياً (منشور فيسبوك يجب أن يُراجع قبل ظهوره على موقع طبي).
🔍 **تحتاج تنبيه فريقك:** المنشورات لن تظهر تلقائياً بعد الآن، بل تحتاج ضغطة «نشر» من الأدمن.

```nginx
server {

server {
    listen 443 ssl http2;
    server_name YOUR-DOMAIN.com www.YOUR-DOMAIN.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # انسخ هنا بلوكات location الثلاثة كما هي من بلوك 80 الحالي
    # ( /api/  و  = /health  و  / )

```

### الخطوة 9 · أضف رؤوس الحماية لتطبيق الويب ⏱️ 15 دقيقة

**كيف تحصل على رابط خريطة جوجل الصحيح:**

2. اضغط «مشاركة» ← تبويب **«تضمين خريطة»** (وليس «إرسال رابط»)
3. انسخ قيمة `src` من داخل كود `<iframe>` فقط
4. يجب أن يبدأ بـ `https://www.google.com/maps/embed?pb=...`

> ⚠️ النظام **يرفض** أي رابط لا يبدأ بهذا الشكل (حماية أضفتها ضد حقن الـ iframe). لو ظهر خطأ 400، فأنت نسخت الرابط الخطأ.

### الخطوة 13 · أوقف النشر خارج نطاق git 🔥 خطر صامت ⏱️ ساعة
**المشكلة المُثبتة:** الإنتاج يشغّل كوداً غير موجود في أي فرع. `deploy.ps1` يرفع مجلد العمل المحلي كأرشيف، لا من git.

**المخاطر:** لا rollback · لا مراجعة · لو انهار السيرفر فالكود ضائع · لا أحد يعرف ما يعمل فعلاً.

**الحل — أضف حارساً في أول `deploy.ps1`:**
```powershell
$dirty = git status --porcelain
if ($dirty) {
    Write-Host "توقف: يوجد تعديلات غير مرفوعة على git." -ForegroundColor Red
    Write-Host "اعمل commit و push أولاً، ثم أعد المحاولة." -ForegroundColor Yellow
    git status --short
    exit 1
}
$sha = git rev-parse --short HEAD
Write-Host "النشر من الكوميت: $sha" -ForegroundColor Green
```

**والأهم:** ارفع الكود الحيّ الحالي على git **قبل** تفعيل هذا الحارس، وإلا ستفقده. اسحب نسخة من السيرفر أولاً:
```bash
scp -r root@169.58.77.61:~/INSAN-Healthcare-Platform/website/apps/web/components/public ./from-server-backup/
```
وقارنها بما عندك.

### الخطوة 14 · أنقذ الصور من الضياع 🔥 قنبلة موقوتة ⏱️ نصف ساعة
**المشكلة:** `apps/web/public/` فارغ في git، لكن الإنتاج يخدم منه ملفات وُضعت يدوياً.

**أول `--build` نظيف من الريبو سيمحوها كلها.**

```bash

scp -r root@169.58.77.61:~/INSAN-Healthcare-Platform/website/apps/web/public/* "J:/My Drive/Insan/website/apps/web/public/"
```

✅ **تأكد:** بعد `docker compose up -d --build` كامل، افتح الموقع وتأكد أن الصور ما زالت تعمل.

### الخطوة 15 · أضف وسوم المشاركة الاجتماعية (Open Graph) ⏱️ ساعة
**المشكلة:** مشاركة أي رابط على واتساب/فيسبوك تظهر رابطاً عارياً بلا صورة.

في `apps/web/app/layout.tsx` أضف داخل `metadata`:
```ts
openGraph: {
  type: 'website',
  locale: 'ar_EG',
  siteName: 'منظومة إنسان للرعاية الصحية',
  title: 'منظومة إنسان للرعاية الصحية',
  description: 'المنظومة الصحية المتكاملة — نربط المرضى بأفضل الكفاءات الطبية في مصر',
  images: [{ url: '/og-image.jpg', width: 1200, height: 630 }],
},
twitter: { card: 'summary_large_image' },
```

وأنشئ صورة `1200×630` باسم `og-image.jpg` في `apps/web/public/`.

ثم أضف `openGraph` مشابهاً في `generateMetadata` لصفحات المستشفى والطبيب والخبر (باستخدام صورة كل عنصر).

✅ **تأكد:** الصق الرابط في محادثة واتساب — يجب أن تظهر صورة وعنوان ووصف.

### الخطوة 16 · أصلح تسميات نموذج الحجز (إتاحة الوصول) ⏱️ نصف ساعة
**المشكلة المُثبتة:** نموذج `/book` فيه 5 حقول إدخال و8 تسميات، لكن **صفر ربط** بينها (`id`/`for`).
قارئ الشاشة يقول «حقل نص» بلا أي توضيح — مريض كفيف لا يستطيع الحجز.

في `apps/web/components/public/AppointmentForm.tsx`، لكل حقل:
```tsx
<label htmlFor="appt-name">الاسم</label>
<input id="appt-name" name="name" ... />
```
كرّرها لـ: `name`, `phone`, `email`, `preferredDate`, `message` وكل قوائم الاختيار.

✅ **تأكد:**
```bash
curl.exe -s "http://169.58.77.61/book" | findstr /C:"htmlFor" /C:"for="
```
عدد `for=` يجب أن يساوي عدد الحقول.
