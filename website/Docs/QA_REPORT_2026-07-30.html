حرج C-1 · صفحة إدارة المواعيد مكسورة بالكامل (500)

الشخصيات: المدير (2/10) · المطور (2/10) · QA (3/10)

GET /admin/appointments يُرجع 500 Internal Server Error في كل الحالات (بلا فلتر، مع pageSize، مع فلتر الحالة) — اختُبر 4 مرات. ونتيجةً لذلك يظهر عدّاد «المواعيد» في الداشبورد كـ «—».

المدير لا يستطيع رؤية أي طلب حجز إطلاقاً — أي أن الوظيفة الأساسية للموقع (استقبال المرضى) معطّلة إدارياً. المرضى قد يحجزون (الإنشاء يعمل) لكن لا أحد يرى الحجوزات.

التشخيص أولاً (خطوة إلزامية): السبب غالباً صف بيانات به مرجع تالف أو قيمة enum لا يعرفها الـ Prisma Client المنشور (متوافق مع مشكلة النشر خارج git). شغّل على السيرفر فور استدعاء الصفحة: 
ssh root@169.58.77.61
docker logs insan-api --tail 60
# افتح صفحة المواعيد في المتصفح، ثم اقرأ آخر خطأ في الـ logs
# ابحث عن: PrismaClientKnownRequestError أو "inconsistent" أو "Invalid value for enum"
الإصلاح الأرجح (توحيد الكود مع قاعدة البيانات): 
# على السيرفر — أعد توليد Prisma Client وطبّق أي migration ناقص
docker exec insan-api npx prisma migrate deploy
docker exec insan-api npx prisma generate
docker compose -f docker-compose.prod.yml restart api
تحصين دفاعي في الكود — الملف apps/api/src/modules/leads/leads.service.ts داخل findAllAppointments، غلّف الاستعلام حتى لا ينهار كل شيء بسبب صف واحد تالف: 
// بدّل include الكامل بـ select آمن، وتحقّق أن العلاقات موجودة
// إن استمر الخطأ بعد migrate deploy، فالسبب صف يتيم (FK لمستشفى/طبيب محذوف)

حرج C-2 · نظام الإعدادات مفصول تماماً عن الموقع العام

الشخصيات: المدير (2/10) · العميل (4/10)

توجد 35 إعداداً في قاعدة البيانات (بريد، هاتف، واتساب، عنوان، ساعات العمل، روابط سوشيال، اسم الموقع) وendpoint عام /api/v1/settings يعمل (200). لكن بحثتُ في كود الواجهة فلم أجد أي استدعاء لها: لا getSettings في public-api.ts، ولا Footer.tsx ولا HomeContactSection.tsx يقرأها.

النتيجة: صفحة «الإعدادات» في الأدمن تبدو كاملة، لكن تعديل أي قيمة فيها لا يُغيّر شيئاً على الموقع. المكوّنات تعرض قيمًا ثابتة مكتوبة في الكود بدلاً منها. وهذا هو مصدر مشكلة بيانات التواصل المتضاربة (C-3).

إضافةً لذلك، قيم الإعدادات نفسها placeholders: contact_phone = "+20-XXX-XXX-XXXX".

الحل جزءان:

1) أضف دالة قراءة الإعدادات — الملف apps/web/lib/public-api.ts في النهاية:

export async function getSettings() {
  const res = await pub<{ success: boolean; data: any[] }>('/settings');
  const map: Record<string, any> = {};
  (res?.data ?? []).forEach((s) => { map[s.key] = s.value; });
  return map; // مثال: map.contact_email, map.contact_phone
}

2) اجعل الفوتر وقسم التواصل يقرآن منها بدل القيم الثابتة (راجع C-3).

3) املأ قيم الإعدادات الحقيقية — استخدم أداة إدخال البيانات المرفقة (تبويب «الإعدادات»).

عالٍ C-4 · لا نظام لرفع الصور (جذر نقص المحتوى)

الشخصيات: المدير (2/10) · العميل (4/10)

12 مركزاً طبياً بلا صورة (heroImage=false للجميع)، والطبيبان بلا صور (photo=false)، وصورتا مستشفى المستقبل /images/future-hero.jpg و/logos/future-logo.png ترجعان 404. ووجدتُ أن مكوّن ImageUpload.tsx أُضيف حديثاً في الكود المحلي، لكن لا يوجد endpoint رفع في الـ API (لا FileInterceptor ولا multer)، وPOST /admin/media غير موجود.

عالٍ C-6 · الموقع على HTTP فقط — بلا تشفير

الشخصية: المخترق الأخلاقي (4/10)

nginx.conf فيه listen 80 فقط، بلا بلوك 443، رغم أن compose ينشر 443 ويركّب مجلد SSL. كلمة مرور الأدمن وكوكي الجلسة يمران بنص صريح.
يتطلب نطاقاً حقيقياً موجّهاً للسيرفر (لا يمكن إصدار شهادة لـ IP). ثبّت Let's Encrypt عبر certbot، أضف بلوك listen 443 ssl، وحوّل 80→443 بـ 301. (خطوات تفصيلية في تقرير FULL_AUDIT_2026-07-29.md الخطوة 7).

عالٍ C-7 · النشر خارج git + مجلد public سيُمحى

الشخصية: المطور (3/10)

الكلاسات على الإنتاج (وحتى الباب الخلفي نفسه) غير موجودة في أي فرع git. deploy.ps1 يرفع مجلد العمل المحلي كأرشيف لا من git. وapps/web/public/ فارغ في git بينما الإنتاج يخدم منه صورًا وُضعت يدوياً — أول --build نظيف سيمحوها كلها.
1) اسحب الكود والصور الحيّة من السيرفر وارفعها على git قبل أي إعادة بناء.
2) أضف حارساً في أول deploy.ps1 يرفض النشر لو فيه تعديلات غير مرفوعة: 
$dirty = git status --porcelain
if ($dirty) { Write-Host "توقف: تعديلات غير مرفوعة على git" -ForegroundColor Red; exit 1 }
3) تأكد أن مجلد المرفوعات على Docker volume دائم.

متوسط C-9 · لا شاشة/endpoint إداري للأسئلة الشائعة

POST /admin/faqs يرجع 404 — لا يوجد endpoint إداري. الجدول FaqItem موجود والعرض العام يعمل، لكن لا سبيل لإضافة سؤال إلا من قاعدة البيانات مباشرة.

متوسط C-13 · لوحة الأدمن بلا رؤوس حماية (Clickjacking)

الشخصية: المخترق الأخلاقي

صفحات Next.js (وفيها لوحة الأدمن) تحمل X-Content-Type-Options فقط. مفقود: CSP، X-Frame-Options، Referrer-Policy. ويكشف X-Powered-By: Next.js.
في apps/web/next.config.js، وسّع headers(): 
{ key: 'X-Frame-Options', value: 'SAMEORIGIN' },
{ key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
{ key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
وأضف poweredByHeader: false.
